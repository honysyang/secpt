# api-recon：API 攻击面收割作战手册

> 给渗透 agent 的方法论 skill（不是给人读的科普）。目标：把一个 Web 目标的
> **真实 API 面**（而非路由表）尽可能完整地收割出来——0day 的入口往往藏在
> 前端代码引用但界面上不可见的端点里。

## 核心模型：静态层 + 运行时层

真实 API 面 = 静态层 ∪ 运行时层。只做任何一层都会漏。

### 静态层：JS bundle harvest

1. 抓首页 → 收集全部 `<script src=...>`（含异步 chunk）
2. 下载全部 bundle（`curl -s` 即可），**必须先复制到工作目录再分析**：
   ```bash
   cp /path/to/bundle.js ./ws/
   ```
3. 提取端点（按收益排序，逐步尝试）：
   - 字符串正则：`"(/[a-zA-Z0-9_./-]{3,})"` 匹配路径字面量
   - URL 拼接：`baseURL + '/xxx'`、`axios.get(\`...\`)` 上下文
   - 环境常量：`VUE_APP_*` / `REACT_APP_*` / `process.env.*` 附近的 URL
4. **门禁：禁止对大 bundle 直接全量 grep 输出**——输出必须 `| head -100` 截断，
   否则会淹没上下文。例如：
   ```bash
   grep -oE '"/[a-zA-Z0-9_./-]{3,}"' ./ws/app.js | sort -u | head -80
   ```

### 运行时层：录 outbound 请求（无凭据撑开 SPA）

很多端点只有登录后/特定交互后才出现在流量里。用浏览器自动化录
**出向请求**：

1. 用 `playwright`（如已装）或 `chromium --headless` 打开目标首页
2. 若页面强制登录：拦截并 stub 登录/bootstrap 接口（mock 返回撑开前端路由），
   只录**出站请求**——不绕过目标服务本身，只是让前端动起来
3. 触发交互：遍历菜单、点击主要功能入口
4. 收集录到的全部 API 调用（方法+路径+参数样例）

### 穷举验证（可选，仅授权范围）

对收割到的端点清单做低强度验证：
- 未认证访问（`curl -s -o /dev/null -w '%{http_code}'`）→ 401/403 与 200 分开记账
- 方法探测（GET/POST/OPTIONS）→ 405 的端点记录允许方法

## 流程门禁（违反即返工）

- [ ]  harvested 端点清单已**去重排序**（同源同路径合并，按目录分组）
- [ ]  每个端点标注来源：静态 / 运行时 / 穷举
- [ ]  401/403 与 200 分开统计（未认证可达是 findings 的原材料）
- [ ]  所有大输出已截断（head/sed 范围），没有把整个 bundle 倒进上下文
- [ ]  分析脚本在工作目录内，按目标改写后再跑（不复用他人脚本原样执行）

## 完成定义（Checklist）

- [ ] 端点清单 ≥ 覆盖：静态层全部脚本 + 运行时全部出站请求
- [ ] 每个 200 端点有最小响应样例（前 200 字节）
- [ ] 每个 401/403 端点标注"需凭据/需授权"（为后续利用链排队）
- [ ] 产出 `record_fact` 写入资产图（endpoint 类型）与观察记录
- [ ] 发现可疑端点时优先 `report_finding`（inferred），不要自行深入利用

## 常见坑（pitfalls）

- 前端路由 ≠ API 端点：`/admin/users` 可能是前端路由，真实 API 是 `/api/v2/members`
- chunk 懒加载：首页没有的脚本，进二级页面才有——至少爬两层
- Source map 泄露（`.js.map`）→ 直接拿到原始源码与全部路由，**优先检查**
- 移动端 API：`/api/mobile/*`、`/m/` 前缀常常是另一套（且更老、更脆弱）
- 版本号残留：`/v1/` 停了但还开着，`/v2/` 有限流 `/v1/` 没有——版本即攻击面
