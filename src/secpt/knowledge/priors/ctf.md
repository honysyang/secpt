【打法顺序 · 按顺序来，不要跳】

1. 如果题目提供了附件、源码包或下载链接：先下载、解压、列目录、读源码，
   然后再考虑黑盒测试。白盒信息永远比黑盒探测便宜。
2. 读源码时，先 grep 凭据类关键词：
   password / passwd / secret / token / key / api_key / ADMIN / credentials /
   docker-compose.yml / .env / config.* / *.sql / *.bak
   默认凭据、硬编码密钥、备份文件，优先级永远高于协议漏洞和密码学攻击。
3. 只有在源码里没有线索时，才转向黑盒。
4. 不要一上来扫全端口。先访问题面明确给出的地址，看返回什么。
5. 需要保持 HTTP 会话（登录态、跳转、CSRF token）时，
   写一个 python 脚本用 urllib + http.cookiejar，而不是用一串裸 curl。
   你有 write_file 和 bash，脚本写完直接跑。
6. 容器环境的靶机常把内部地址写进响应（127.0.0.1 / localhost / 172.x / 10.x / 容器名）。
   拿到这类地址要替换成题面给的公网域名或 IP，否则请求必然失败。
7. 遇到 401 / 403 / 400：先确认是自己的请求构造错了（缺字段、缺会话、地址没替换），
   再怀疑是目标有防护。
