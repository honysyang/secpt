# 工作循环形态设计（Loop Design v1）

> 状态：**设计稿**（未实现）。评审通过后按 §7 分阶段落地。
> 输入：一次横评的结论——"市面循环形状无秘密，分野在四件事：怎么体面地停、
> 怎么不失忆地活、怎么有尊严地重启、怎么独立地验"。本文把这四件事落成
> secpt 的循环形态。

## 0. 现状与缺口（设计输入）

**已有（保留，不推翻）**：
- L2 单链 Engine：ReAct JSON 工具循环、append-only 语义、四触发器卡死检测
  + 可行动 nudge + 冷却节流、非阻塞 compaction（分段摘要）、rollover（0.95）、
  budget 80% 注入/100% 优雅收尾、resume/checkpoint（rounds 快照）。
- L1 frontier：planner↔worker 持久编排、意图租约/依赖/复核/单编排锁、
  verify/report 确定性触发、prove_goal 量化验收。
- 治理与证据：scope/intercept/audit、findings 对抗式复现、judge 反作弊。

**缺口（本设计解决的问题）**：
| # | 缺口 | 后果 | 市面对照 |
|---|---|---|---|
| A | 循环内止损是**回合级**（watchdog 60 步边界） | 最坏 ~75 分钟才发现空转 | Claude Code token budget：滚动窗口边际收益，分钟级 |
| B | 无"收尾注入"档位——nudge 无效后只能等硬预算墙 | 预算打得难看，没有体面收场 | OpenCode：超步数注入 max-steps 消息强制总结 |
| C | rollover 是"同一会话换链"，没有**主动重置**语义 | 长任务里上下文带着旧假设越跑越脏 | Devin/Anthropic："restart beats patching; sink state into files" |
| D | planner 自由发挥，编排层缺**状态驱动的阶段路由** | 规划质量随模型状态波动 | LangGraph：结构化 state 做确定性路由 |
| E | 验证与执行同 prompt 同会话 | 自我确认偏差 | MAPTA/XBOW/PentAGI：validation 独立成角色 |
| F | 目标演化无受控通道（只能人 steer） | 侦察推翻题面假设时，agent 无法提议改向 | Manus 自由改写（无治理）/ plan mode 人工批准 |

**设计红线（继承，不可破坏）**：
1. messages append-only（收尾注入也是**追加** user 消息）；
2. 治理链（scope→intercept）在每次命令执行前，不受循环状态影响；
3. 学习/评判/观测 best-effort，绝不阻断主链路；
4. 一切阈值可配（env），一切新增事件登记 EVENT_CATALOG。

## 1. 三层循环总图

```
L0 任务循环（每任务一次，进程级）
   solve/hunt → 路由 → 拆解(GoalSpec) → [L1] → 评判 → 学习 → 演化提案闭环
   状态：task.yaml / GoalSpec / frontier.sqlite / experiences

L1 编排循环（planner ↔ worker，持久，跨进程跨重启）★本设计增强
   ┌─ planner 轮 ──→ 意图入队 ──→ worker claim ──→ [L2] ──→ settle
   │                                                    │
   └──── 复盘会 retro()（确定性，状态驱动三选一）←────────┘
        ├─ 继续：常规 planner 轮
        ├─ 局部递归：失败驱动展开子意图（ADaPT 语义）
        ├─ 收敛：verify → report
        └─ 演化提案：goal_revision 进人工确认队列

L2 执行循环（Engine 单链，模型↔工具）★本设计核心
   RUNNING ──nudge──→ NUDGED ──无改善──→ WRAPPING ──未收敛──→ STALLED
      │                  │                   │                    │
      │                  └─ 改向则回 RUNNING  └─ 收敛则 END        └─ 交 L1：
      └─ ANSWER/prove_goal 通过 → END                                RESET 或终态
```

职责边界：**L2 只管"这一步怎么做好"，L1 管"下一步做什么 / 是否需要改变方向"**。
止损决策全部由状态机做，模型只负责内容质量（不要求模型"自己知道该停了"——
Cognition context anxiety 的教训）。

## 2. L2 执行循环：三档止损状态机（核心交付）

### 2.1 状态与迁移

| 状态 | 含义 | 进入条件（默认值，env 可调） | 行为 |
|---|---|---|---|
| RUNNING | 正常推进 | 冷启动 / NUDGED 后检测到改向 | 现有主循环 |
| NUDGED | 已提醒一档 | 四触发器命中（**现有逻辑，不变**） | 追加 nudge user 消息（现有文案） |
| WRAPPING | 收尾期 | ① nudge 后 `SECPT_WRAP_AFTER_NUDGE=8` 步仍无结构性新增；② 或步数/预算达 `SECPT_WRAP_AT_PCT=90%` | 注入**收尾指令**（追加 user 消息，模板见 2.3）：只允许"总结/验证/交付"类动作；工具仍全部可用（治理链不变） |
| STALLED | 判定卡死 | WRAPPING 后 `SECPT_STALL_AFTER_WRAP=8` 步未产 ANSWER | `RunResult.status="stalled"`，Engine 优雅退出（落 transcript/rounds，**不抛异常**）|
| END | 终态 | ANSWER + prove_goal 通过 / 硬预算 / STALLED | 现有收尾路径 |

**关键约定**：
- NUDGED 回退：若 nudge 后出现新的结构信息（stuck detector `update()` 返回 True），
  回 RUNNING 并重置 wrap 计数（提醒有效，不升级）。
- WRAPPING 不锁工具、不锁治理——它只是**提示 + 记账**。真正收口的是 STALLED。
- 三级全部**可观测**：`loop_nudged_total / loop_wrapping_total / loop_stalled_total`
  三个 counter + events（新增 `loop_phase` 事件，登记 EVENT_CATALOG）。

### 2.2 滚动窗口边际收益（把 A 缺陷补上）

现有 `StuckDetector` 检测的是"结构性新信息"（签名）；**收益递减**是另一个维度：
近 N 步就算有"新信息"但没有**成果性产出**（finding/凭据/资产/新事实入图），
且每步成本高——这才是真正的烧钱空转。设计：

- 编排层 hooks 已有 `on_finding`（成果）与 `on_tokens`（成本）——Engine 内
  维护滚动窗口：
  ```
  SECPT_MARGIN_WINDOW=20        # 窗口步数
  窗口内 成果数=0 且 窗口成本 > SECPT_MARGIN_COST_CNY=0.05  → 触发 WRAPPING（文档 1 档）
  ```
- 与 watchdog（回合级）关系：watchdog 管**跨回合方向**（换层提示），本机制管
  **回合内止损**（收尾注入）。两者互补，不替代。
- metrics：`loop_margin_wrap_total{reason="no_yield|budget_pct"}`。

### 2.3 收尾指令模板（压力注入，OpenCode 模式）

```
【收尾阶段】本步起进入收尾：剩余预算有限/本策略收益已趋零。
只做三件事（严禁开新战线）：
1. 用你已确认的事实给出当前结论（含证据：文件:行 / step N / 响应片段）
2. 列出未完成项与已验证否定的路线（防后续会话重复踩坑）
3. 以 ANSWER: <结论> 收尾（有 flag 给 flag；没有就给当前结论摘要）
```

### 2.4 挂点（代码级）

- `runtime/engine.py`：主循环 while 体内插入状态机（约 40 行）；
  `detector.update()` 返回值已够驱动 NUDGED→RUNNING 回退；
  WRAPPING 注入走现有 `messages.append(user)` + `hooks.on_user_message(kind="wrap")`；
  STALLED 作为新 `RunResult.status`（docs/架构现状.md 状态表同步）。
- `runtime/stuck.py`：**不改**（四触发器职责不变）；wrap/stall 计数放 Engine。
- 兼容：`SECPT_LOOP_STOP=0` 一键回退旧行为（只留 nudge + 硬预算）。

## 3. RESET：把 rollover 升级为主动重置（补 C 缺陷）

### 3.1 何时 RESET（编排层决策，L1）

worker 返回 `status="stalled"` 或 `wallclock_exceeded` 时，编排层（`_run_one`）按序判断：

```
还有意图预算? ──否──→ exhausted（现有）
   │是
已 RESET 过一次? ──是──→ exhausted（复核已由"首轮失败自动复核"覆盖，防死循环）
   │否
ws 有实质产出(_has_ws_output)? ──否──→ exhausted（空转不续，现有语义）
   │是
→ RESET：新子 job（-r2，复用现有续跑机制）从外部状态重建上下文
```

### 3.2 RESET 的"外部状态"（restart beats patching 的落地）

新会话首条 user 消息 = 四件套（全部已有基建，只做组装）：
1. **handoff 六段摘要**（现有 summarizer，对旧 transcript 生成）；
2. **ws 产物清单 + 复制**（现有 `_carry_ws_artifacts`）；
3. **intel 图事实回灌**（现有 `recall_graph(意图关键词)`）；
4. **否定清单**（现有 recent_results 的 exhausted fail_reason 聚合）。

与 rollover 的区别：rollover 是**同一会话内**换链（保留前缀缓存收益、丢会话历史）；
RESET 是**换会话**（丢缓存、换新链语义）——只在"策略级卡死"时用，每意图上限 1 次。
判据：`stalled` 触发优先 RESET；撞墙型 `wallclock_exceeded` 看 ws 产出。

- metrics：`loop_reset_total{outcome="recovered|exhausted"}`。

## 4. L1 编排循环增强

### 4.1 复盘会 retro()（补 D 缺陷，LangGraph 状态机思想）

每次 settle 后，编排层跑一个**确定性函数**（零 LLM、纯 SQL/计数），输出阶段决策：

```
输入（全部现成）：chains 增量 / intel 新增事实与资产 / 覆盖度变化 / exhausted 清单 / wake 原因
输出（三选一，直接决定主循环下一步）：
  continue    → 常规 planner 轮（现状路径）
  recurse      → 失败驱动局部递归（4.2）
  converge     → 强制走 verify→report 收敛判定
触发规则（首批，保守）：
  converge: 全部 workstream/子目标 settled（现有 all_subgoals_settled 扩展）
  recurse : 同一 intent 复核后仍 exhausted 且 fail_reason 属"路线型失败"
            （step_exceeded/wallclock），且其 asset 尚无任何 confirm
  continue: 其余
```
作用是**把"planner 该不该再规划"从模型状态里拿出来**（现状 `idle_rounds>=2` 是
唯一的确定性收敛判据，太粗）。planner 依旧自由产意图——但**阶段**由状态定。

### 4.2 失败驱动的局部递归（ADaPT 语义，补"深度拆解"缺口）

recurse 触发时，编排层直接产**结构化子意图**（不经 planner LLM，纯代码）：

```
父意图（exhausted, asset=A, 路线 R 失败）
→ 子意图 1: role=recon  asset=A   "对 A 枚举此前路线 R 未覆盖的表层（读源码/robots/API 目录）"
   done_criteria: "产出 ≥1 条新端点或明确证明无"
→ 子意图 2: role=exploit asset=A  done_criteria 同父，depends_on=子1，depth+1
```
要点：**只在失败时展开**（ADaPT 核心），每父意图最多展开一层（防递归爆炸），
子意图走正常租约/复核链。planner 也可以产同类意图——两条路并存，编排层这条
保证"planner 忘了展开"时系统仍会动。

### 4.3 验证独立化（补 E 缺陷）

现状：verify 意图 = 独立子 job（会话独立 ✓）但同模型同 prompt。
增强（配置级，一行变更）：
- `SECPT_VERIFY_MODEL`（缺省=主模型）：verify 子 job 可指定不同模型——
  推荐配一个异构模型（不同厂商），把"同模型同盲区"概率打掉；
- verify 的 system prompt 走 `roles.role_stage("verify")`（已有）+ **禁 read 旧
  transcript**（防照抄原证据）——verify 意图 objective 已只带 finding 描述
  （build_intent_objective 的共享情报段），补一条硬约束进 role_stage 文案。
- MAPTA/XBOW 对照：validation agent 独立容器 + 独立凭据——secpt 的独立子 job +
  独立容器（F2 后每 job 一容器）已对齐 80%，缺的是模型异构与"禁止复用原会话"。

### 4.4 演化提案通道（补 F 缺陷，受控版 Manus）

```
触发（复盘会内，确定性）：题面 asset 之外的资产在 intel 图中占比 > 50%
                          且 ≥2 条 confirmed 无关 finding
产出：goal_revision 意图（source="revision"，role="report" 的特殊形态）
处置：默认进 intercept pending 队列（复用审批基建）：
  SECPT_GOAL_REVISION=auto   纯"细化"（不扩 scope）自动批准并重渲染 objective
  SECPT_GOAL_REVISION=ask    （默认）人工审批
  SECPT_GOAL_REVISION=off    关闭
批准后：重新走 decompose → filter_goal_assets（scope 重校验）→ planner 换目标
纪律：扩 scope 的提案**永远 require 人工**（ROE 是不可自动化的边界）
```

## 5. 参数总表（全部 env，缺省即当前行为）

| env | 缺省 | 作用 |
|---|---|---|
| SECPT_LOOP_STOP | 1 | 0=关闭三档止损（回退旧行为） |
| SECPT_WRAP_AFTER_NUDGE | 8 | nudge 后无改善多少步进 WRAPPING |
| SECPT_WRAP_AT_PCT | 90 | 步数/预算到该百分比直接进 WRAPPING |
| SECPT_STALL_AFTER_WRAP | 8 | WRAPPING 后多少步未收敛判 STALLED |
| SECPT_MARGIN_WINDOW | 20 | 边际收益滚动窗口（步） |
| SECPT_MARGIN_COST_CNY | 0.05 | 窗口成本阈值 |
| SECPT_RESET_MAX | 1 | 每意图 RESET 上限 |
| SECPT_VERIFY_MODEL | ""（=主模型） | verify 子 job 模型（建议异构） |
| SECPT_GOAL_REVISION | ask | off/ask/auto |

新增 events：`loop_phase`（nudged/wrapping/stalled/reset，登记 EVENT_CATALOG）；
新增 metrics：`loop_nudged_total / loop_wrapping_total{reason} / loop_stalled_total /
loop_reset_total{outcome} / loop_margin_cost_cny`。

## 6. 与市面安全/通用智能体的对照（设计依据）

| 设计点 | 参照 | 差异 |
|---|---|---|
| 三档止损状态机 | Claude Code tokenBudget + OpenCode 压力注入 | secpt 额外把 STALLED 交还编排层（市面多为直接结束） |
| RESET（状态外置重建） | Devin/Anthropic "restart beats patching" | secpt 把 RESET 变成有预算判断的编排动作，非默认策略 |
| retro() 状态驱动路由 | LangGraph 状态机终止 | 落点是"阶段"而非"终止"，planner 自由度保留 |
| 失败驱动递归 | ADaPT（as-needed decomposition） | 编排层确定性展开 + planner 自由产意图双轨 |
| 验证独立化 | MAPTA Validation Agent / XBOW 盲测 / Strix PoC | 独立 job/容器已有；补模型异构与禁复用会话 |
| 演化提案 | plan mode（人工门）+ 契约细化研究（2610.04975） | 提案权归 agent、决定权归人（scope 扩权永不自动） |

## 7. 分阶段落地与验收

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P1** | §2 三档止损 + 滚动边际收益（engine 内，~120 行） | FakeLLM 卡死脚本：nudge→wrap→stall 三跳可测；50 步空转的假任务在 wrap 后拿 ANSWER 而不是烧满预算；`SECPT_LOOP_STOP=0` 回退全绿 |
| **P2** | §3 RESET（frontier `_run_one`，~80 行） | stalled 意图自动 -r2 重建且 handoff 含四件套；空转意图不 RESET（走 exhausted）；每意图上限 1 次 |
| **P3** | §4.1 retro() + §4.2 失败递归（~100 行） | 复核后仍败的意图触发子意图展开且带依赖；收敛判定与现有一致（回归 test_orchestrator 全绿） |
| **P4** | §4.3 验证异构 + §4.4 演化提案（~120 行） | verify 用 SECPT_VERIFY_MODEL 实际生效；提案默认进 pending 且 scope 扩权不可自动批准 |

每阶段独立可回退（env 开关 + 既有测试基线 679 全绿 + 新增单测）。

## 8. 明确不做的事

- 不引入树搜索/ToT 式循环（生产成本不成立，S5 已退役同类）；
- 不把"何时停"交给模型判断（Cognition 教训——由状态机定，模型只管内容）；
- 不自动扩 scope（ROE 边界：演化提案可自动的只有"细化"类）；
- 不改 stuck.py 四触发器语义（本设计只加"档位"，不动"检测"）。
