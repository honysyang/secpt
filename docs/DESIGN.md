# secpt 渗透智能体 · 架构设计说明

> 配套图：`pentest_agent_arch.png`（2000×2860，由 `arch.py` 生成，可改参数重新出图）
> 版式借鉴 Hermes Agent 架构图：多客户端 → Agentic Loop → 上下文/LLM → 三层记忆 → 状态库 → 事后复盘自进化。
> 仅面向**获得书面授权**的渗透测试、红队演练与靶场评测。

---

## 1. 和 Hermes 参考图的对应关系

| Hermes Agent | 本设计 | 设计意图 |
|---|---|---|
| 多客户端 TUI / Web / 桌面 / SDK | **+ Bot 通道（钉钉/飞书/企业微信）、远程遥控** | 长任务需要“人不在电脑前也能接管”，与 ZCode 的 Remote Control / Bot Channel 思路一致 |
| Loop：Terminal / Browser / 定时任务 / 任务分发 / MCP | 同上，**MCP 换成“工具池”**（nmap/nuclei/sqlmap/fscan 等）并保留 Sub Agent | 渗透是长链路循环：侦察→利用→提权→横向→取证 |
| working memory + user/sys prompt/chat history + LLM + 回复 | 同构；**加 RAG/sql 双通道** | 事实类信息（目标、凭证、攻击图）走 SQLite，知识类走语义记忆 |
| 程序记忆 / 语义记忆 / 情景记忆 | 同构，但内容变为**攻击 SKILL、漏洞语义、历史战役** | 自进化落点：复盘后自动改 SKILL，而不是只记用户偏好 |
| SQLite state.db（FTS 索引） | 同构 | 目标/凭证/会话/攻击图谱/证据链统一落库 |
| 知识整合门控（菱形） | 同构，**加入“证据校验 + 人审”** | 渗透结论要可复现，避免模型把误报写进长期记忆 |
| Background Review Agent | 同构 | 每轮任务结束后异步复盘，提炼规则、剔除误报 |

新增（渗透场景必须有）：**授权与安全网关**——这是与通用编码智能体最大的区别，见第 4 节。

## 2. 分层说明

### 2.1 接入层（多客户端）
- **TUI**：终端交互 + 批量评测（类似 `--prompt` 非交互调用），适合写在 CI 或演练脚本里。
- **Web 控制台**：监听 127.0.0.1，局域网访问需开 token。
- **桌面端**：Electron 工作台，内置终端/浏览器/预览面板。
- **SDK / API**：给 SOC 编排、告警联动、自动化回归用。
- **Bot 通道 / 远程遥控**：手机或 IM 里补指令、看进度；**只做控制面，不新建运行环境**。

### 2.2 编排层（Agentic Loop）
6 个能力槽位：
1. **Terminal**：Shell / SSH / 反弹会话（原始终端、PTY）。
2. **Browser**：Playwright 驱动内置浏览器，用于 Web 漏洞验证与登录态复现。
3. **任务分发**：Planner 把目标拆成 DAG，分派给 Sub Agent（侦察/枚举、利用/横向，可再扩 Web/域）。
4. **定时任务**：cron 控制攻击窗口（避开业务高峰）、定期回归复测。
5. **记忆管理**：读写 SKILL / 语义记忆 / 情景记忆。
6. **MCP 工具池**：把 nmap、nuclei、sqlmap、fscan、impacket 等封装成 MCP 工具，统一 schema 与权限声明。

### 2.3 上下文与模型
- `user prompt`（目标与授权范围）+ `sys prompt`（角色、ROE、禁止清单）+ `chat history` + 记忆检索结果 → **working memory** → LLM。
- **RAG / sql** 两个标注：语义记忆用向量检索，目标事实与攻击图用 SQL 精确查询。
- **模型层多供应商**（GLM-5.3、DeepSeek、Claude、Kimi、Qwen、MiniMax、私有化模型），**推理强度可调**：
  - 简单指纹匹配用低档，省钱省时；
  - 复杂绕过、链式利用用最高档。
- 敏感数据（客户资产清单）建议**私有化模型 + 本地 embedding**。

### 2.4 三层记忆
| 层 | 存什么 | 文件/存储 | 写入者 |
|---|---|---|---|
| 程序记忆 | 攻击技能、工具调用习惯、跳步经验 | `~/.pentest/skills/*.md` | **复盘 Agent 自动写**（人审后合并） |
| 语义记忆 | 漏洞语义、指纹→利用链、ATT&CK 映射 | `~/.pentest/memory/MEMORY.md` | 复盘 Agent + 人工整理 |
| 情景记忆 | 每次渗透的事件序列、战果、时间线 | SQLite `episodes` + FTS5 | 运行时自动记 |
| 状态库 | 目标、凭证（加密）、会话、攻击图谱、证据链 | SQLite `state.db` | 运行时 |

**检索路径**：working memory 用关键字/topic 查 FTS，命中后按需 `skill.md 注入`；命中不足再走向量 RAG。

### 2.5 复盘与自进化
```
任务结束
  → Background Review Agent 读取会话日志/回显/证据
  → 判断本轮是否产生：新攻击链 / 可复用指纹规则 / 失败教训 / 旧 SKILL 纠正
  → 提炼事实与规则
  → 知识整合门控（去重、冲突检测、证据校验、人工审核）
  → 写入程序记忆 / 语义记忆 / 情景记忆
  → 下一轮任务自动加载新 SKILL
```
> 关键：**门控是必经环节**。没有证据或证据不足的“结论”只能进情景记忆当草稿，不能升级为 SKILL。

## 3. 关键数据流

1. **入战**：客户端提交目标 → 网关解析授权范围 → 写入 `state.db.targets`。
2. **规划**：Planner 读 SKILL + 历史情景 → 生成 DAG → 分派 Sub Agent。
3. **执行**：每个工具调用前过网关（范围、速率、高风险确认、隐蔽度、审计）。
4. **回显**：工具输出进入 working memory，同时落 `state.db` 的证据链。
5. **循环**：LLM 依据结果决定继续/换招/收口。
6. **收口**：生成报告与 POC → 回复。
7. **复盘**：Review Agent 提炼 → 门控 → 沉淀。

## 4. 授权与安全网关（核心差异点）

| 能力 | 做法 |
|---|---|
| 范围守卫 | 白名单：域名 / CIDR / 端口 / 路径前缀；**每一跳**（含 DNS 二次解析、重定向）都复验，防 SSRF 式越界 |
| 速率与窗口 | 每目标 qps、并发、时间窗（如只在 22:00–06:00 探测） |
| 高风险确认 | 凭证窃取、数据导出、关停服务、DoH/横向移动等需人工点击放行 |
| 隐蔽度闸门 | 噪音等级分档：静默扫描 / 常规 / 激进，由客户 ROE 决定上限 |
| 全量审计 | 每条命令、参数、输出摘要、时间戳、操作者，可导出报告；满足合规留痕 |
| 熔断 | 触发告警联动或蜜罐告警时一键停手 |

**原则**：权限系统本身不是安全边界——真正的作用域限制必须由容器/网络策略/跳板机实现，网关负责“意图校验 + 留痕”。

## 5. 落地建议

- **第一版**（2–3 周）：TUI + CLI 壳子 → Terminal/Browser 工具 → SQLite 状态 → 单 Agent，先跑通内网靶场。
- **第二版**：加 SKILL 记忆 + 复盘 Agent + 门控，验证“越用越准”。
- **第三版**：多客户端（Web/桌面/Bot）、Sub Agent 并行、多模型路由。
- **评测**：用靶场或已授权的脆弱环境做 cold-start 对比（有/无记忆），指标：漏洞命中率、误报率、平均步数、耗时、危险动作拦截率。

参考：ZCode CLI 的文档里对“工具注册过滤 → 权限判定 → Hook → 执行 → 结果回填”这条链路的描述，与本设计第 3 节一致，可直接借用其工具/权限/Hook 的设计经验。
