# 对标 ARTEX：顶级渗透智能体的十条原则（用户提炼 · 2026-10-12）

> 核心论断：**顶级渗透智能体拼的是工程闭环，不是模型更聪明。**

## 十条原则

1. **状态必须外置**——资产/进度/事实/漏洞/证据全部落库；模型每轮从库读态势再决策；
   会话可重启、任务可暂停/恢复/交接；上下文只放本轮信息，长记忆交给数据库和文件
2. **规划与执行分开**——planner 判全局、产意图；worker 领单条意图执行、写回、唤醒 planner；
   planner 不陷在单次命令里，worker 不擅自扩大范围
3. **双图管记忆**——资产图（跨任务共享真值）+ 探索图（本任务推进链，结论可溯源）；
   归属/去重/层级由程序算，模型只交原始观察
4. **攻击链按依赖推进**——多步链进共享待办，只派前置已满足的步骤；新事实解锁后续；
   无状态模型也能稳定走完有顺序的攻击链
5. **并行执行但共享线索**——worker 可并行，且能检索彼此执行过程；中间日志里的线索
   未必马上成结论，过程共享让分散观察拼回完整画面
6. **安全边界是硬机制**——授权/审批/留痕/沙箱/预算由系统强制执行；模型提动作、
   运行时决定能否执行；高危默认拦截人工放行；请求响应全量留存，报告绑定不可变证据
7. **漏洞结论要独立验证**——对照请求/响应/差异/影响范围，独立校验确认；
   复测分"仍可复现/已修复/无法确认"，直接压误报
8. **给 AI 装专业方法论**——侦察/认证/权限/注入/业务逻辑经验写成可复用技能；
   模型负责推理，专家流程约束方向
9. **产品体验同样重要**——覆盖图/探索链路/流量回放/漏洞分级/人工对话/实时日志，
   让人快速判断 AI 有没有跑偏
10. **评估体系跟上**——除成功率外跟踪：覆盖率、误报漏报、平均发现时间、Token 成本、
    人工干预次数、恢复能力；成熟标志=中断可续跑、失败可回滚、换模型仍交付

## 目标骨架

```
权限边界 → 资产图 → 探索图 → 规划队列 → 执行沙箱 → 证据库 → 验证器 → 报告
        任何一环薄弱，整个系统都会在前线翻车
```

## 附录：ARTEX 三种工作模式与五角色小队（用户提炼 · 2026-10-12）

**三种模式**：
1. **自主探索**（最常用）：给目标+授权范围 → 目标拆解器拆子目标 → 规划者持续判态势
   产动作 → worker 领取执行写回 → 循环至目标完成或无新方向（没方向不派任务，防空转烧钱）
2. **人工直投意图**：目标已完成后启用；规划者暂停，人直接下发具体意图，worker 执行完即停
   （“人点单、AI 干活”，不再重新规划）
3. **人在环路干预**（贯穿全程）：随时查看进度/调整重点/注入提示/高优意图；越界或高危
   命令触发拦截规则 → 暂停等人工审批

**五角色小队**：“有人定目标、有人做计划、有人动手测试、还有人复查漏洞”

| 角色 | 职责 |
|---|---|
| 目标拆解器 | 任务创建时一次性：大目标拆小目标 + 登记授权范围（越界判断依据） |
| 规划者 | 调度员：资产/结果一更新就读双图，判目标是否达成，往待办队列放下一步；无新方向不派 |
| 工作智能体 | 真正调工具（枚举/扫描/注入），每次认领一个待办，完成写回即停；默认 3 个并发 |
| 主智能体 | 人的入口：看进度/调重点/自然语言指令转提示或高优动作 |
| 复测智能体 | 任务结束后新会话重验漏洞：仍可复现/已修复/无法确认 |

**主循环**：人给目标和范围 → 拆解 → 规划 → 执行写回 → 数据库变化唤醒规划者 → 循环。
关键一句：规划者决定“下一步测什么”，worker 负责“把这一步跑完”，状态全在数据库。
