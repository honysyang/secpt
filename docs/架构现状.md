# secpt 架构现状（Phase A + 易用性/学习/插件轮后）

> 本文档是当前实现的权威描述。`secpt-开发文档.md`（v0.3）描述的 Phase 2
> 分形 Node 树/波前调度/Evaluator 已在 S5 删除（见 `core/orchestrator/policy.py`

## S6 模式收敛（2026-10-19，权威）

**单一执行编排 = frontier 意图驱动。** 原三种执行模式已收敛：

| 原模式 | 现形态 |
|---|---|
| single 单链（默认） | frontier 探索型：`max_workers=profile.workers`（缺省 1）、planner 自由规划、`stop_on_first_flag`（单资产）。失败恢复由意图复核/RESET/升级强模型承担 |
| stages 多阶段 | `run_frontier(stages=...)`：profile.stages 折叠为线性 depends_on 意图链（清单型，planner 以 `max_intents=len(stages)` 关闭；阶段预算/工具/收尾条件映射意图字段；交接复用 M1 同资产 asset_state 搬运） |
| frontier 团队（--mode frontier） | 多资产 → 通用独立任务并行（v3 默认）；旧 `role_plan=True` 角色骨架保留，仅 `SECPT_ROLE_TEMPLATES=1` 时启用 |
| benchmark campaign | 保留（平台协议层：拉题/结算/账本防双开；内部即 run_frontier，不是 --mode 语义的"模式"） |

- 统一路由：`dag.run_task` —— benchmark → campaign；其余 → frontier（augment_objective 拼
  【目标入口】【附件源码】；`spec.budget.steps` → `default_max_steps`；`wall_s>0` → `deadline_ts`）
- `profile.workers`（loader.py，缺省 1）数据驱动并发：pentest=3 / redteam=4 / hunter=2
- 已退役（DEPRECATED_MODULES 硬约束）：`run_single_chain`（attempt-2/r2 固定重试）、
  `stages.py` 执行器（Stage 数据模型保留在 loader.py）、`route_policy`、CLI `--mode`
- solve 失败升级路径（单链→frontier 二次升级）随之删除——升级语义内聚为 frontier 的
  复核/recheck

## v4 工作循环（2026-10-19，叠加在 v3 上）

对应"值守层 Watch + Commander + 假设树"的工作循环形态。核心原则：LLM 只做必须
判断的事，其余全是确定性代码；值守层是常驻心脏，主智能体是被唤醒的。

1. **假设树（orchestrator/hypothesis.py）**：Commander 的世界模型。SQLite
   `var/jobs/<base>/hypothesis.sqlite`，节点状态机 `proposed → testing →
   confirmed/refuted/dead`（testing → refined 经 refine() 生子）。入口硬校验：
   必须带可证伪陈述 statement + 判定实验 test；confirmed/refuted 必须附证据指针。
   表 `evidence_events` 存值守层攒下的未消化证据，Commander 唤醒时逐条结算消费。
2. **值守层（orchestrator/watch.py，零 LLM）**：
   - 失败类型化：`classify_failure` 把引擎结果分为 tool_failure（自动重试不惊动
     Commander）/ budget_exhausted（硬止损）/ stuck（Coach）/ negative（实验成功
     执行结果为负——是信息不是故障）/ success / capability_gap（需求清单）。
   - 触发器（确定性，便宜→贵）：预算里程碑（墙钟/意图配额 30/50/75%，每档一次）、
     phase gate（全子目标结算，已有）、stall（连续 N 次评估无信念增量——done 意图数
     + 假设终态数，不是无产出）、巩固定时器（每 6 轮强制内务唤醒）。
     矛盾报警依赖 intel 冲突检测，未实现（TODO）。
3. **Commander（orchestrator/commander.py）**：无状态事件驱动。每次唤醒是全新
   短会话，输入为确定性简报（假设树 digest + 未消化证据 + situation_report + 触发
   原因 + 当前战略文档），输出 JSON：beliefs（信念结算）+ hypotheses（新假设）+
   decision（continue/pivot/shrink/deliver）+ tasks（复用 v3 triage 分流入池）+
   strategy（全量重写战略文档）。双载体：`var/jobs/<base>/strategy.md`（固定四段：
   当前阶段/主攻方向/明确不做/转向日志）+ 假设树。
   - 防漂移闸：新战略文档与旧版 diff，主攻方向 bigram 重叠 <0.45 且转向日志无新增
     论证 → 拒收新文档（保留旧版），信念/任务照常生效。
   - 决策为 deliver → 置 delivery_pending，交给交付门裁决。
4. **信念性收敛**：主循环空队列且 idle≥2 时，若假设树仍有活动高价值节点
   （`tree.open_high_value()`）→ 不收口，以 stall 信号唤醒 Commander 继续派单
   （stall_wake_budget=2 封顶防打转）。收敛=目标达成/无高价值未决节点/预算耗尽。
5. **确定性信念增量**：意图结算时（_run_one 尾部），挂靠假设的任务 done →
   proposed→testing→confirmed（证据=子 job）；negative/budget → 落未消化证据
   （Commander 精结算）；stuck → Coach。`intents.hypothesis` 列（自动迁移）挂靠。
6. **内务修剪**：挂靠假设 dead/refuted 的未开始任务逐轮取消（启动时也剪一次，
   覆盖 resume 场景）。
7. **收敛排空后勤**：交付门前取消未开始的 logistics 任务、等待在途后勤回写
   （有界：后勤自带步数/墙钟预算）——解决主路径完成但后勤在飞的收敛竞态。
8. **异构复验**：交付复核任务要求换工具路径（traffic replay 优先于重发请求）+
   证据锚定（哈希/文件路径），对冲同构重跑的系统性误判。

### v4.1 六维改造（2026-10-19，叠加在 v4 上）

- 智能体层：**假设上下文注入**——挂靠假设的任务 objective 注入 statement/判定实验/置信度/已有证据（执行体知道自己在验证什么，实验围绕判定实验设计）；结论模板强制**证据锚定**（文件路径/输出摘录/哈希）。
- 协作层：**后勤成果回注**——build_intent_objective 注入「后勤已完成」小节，主任务直接取用不重复准备；Commander 派单**标题归一化去重**（防多轮唤醒重复派同一任务）。
- 作战地图：**防御信号检测**——settle 时扫描工具输出，同一特征（403/限流/WAF/蜜罐）反复出现 ≥3 次 → [defensive] 未消化证据（"打不动可能不是技术问题，是防守方反应"交给 Commander 改向）。单次 403 不计。
- 数据层：**工作区搬运 manifest.json**（_carry_ws_artifacts 持久化清单，复验/审计可核对）。
- 编排层：**交付回滚**——复验耗尽仍未验证 → confirmed 假设置信度 ×0.6 + [rollback] 证据（确认偏误的结构性对冲）；**能力缺口出口**——工具输出级缺口扫描（command not found 等）→ [capability_gap] 证据 + 原始输出片段（需求清单，Commander 裁决）。
- 效率层：**后勤并发可配**（SECPT_LOGISTICS_WORKERS，默认 2，上限 4）；派单去重减少无效 worker 预算消耗。

开关：`SECPT_ORCH_COMMANDER=0` 回退 v3 planner（benchmark/stages 清单型强制回退）；
观测点进 summary extras：`commander_wakes` / `commander_deliver_requested` /
`hypothesis_counts`。Sub-planner（方向子规划器）按设计挂起，等"多方向信念更新互相
挤占"的实测信号再建。

## v3 执行编排增强（2026-10-19，叠加在 S6 上）

v3 对应"主智能体 Plan-and-Execute + 通用执行体 ReAct + 后勤/交付/教练"的架构路线：

1. **默认无角色模板**：planner prompt 产彼此独立的通用任务，不要求 role/depends_on；
   `plan_round` 用 `triage` 决定 main/logistics。旧 recon/exploit/lateral/verify/report
   角色体系只剩 legacy 开关 `SECPT_ROLE_TEMPLATES=1`（含 role_stage 注入与失败递归）。
2. **main/logistics 双通道**：`intents.lane`（默认 main）；main worker 只领 main；
   独立 logistics worker 只领 logistics。主循环的收敛/规划只按 main 计数，后勤不阻塞
   主路径。执行体可调用 `delegate_logistics` 入队（`frontier._make_delegate_logistics_tool`），
   工具立即返回，后勤完成后把结果写入任务池/工作台。
3. **JEV/快判**：`triage.py` 规则判断任务分级、风险、main vs logistics、结果快检；
   `SECPT_ORCH_JEV=1` + `JEV_API_KEY` 时可让外部 typed JevGate 参与 lane 判断（低置信
   自动回退规则）。
4. **交付门**：`delivery_gate.py` 在主路径排空后核对 flag/证据；flag 没有独立复验 →
   生成一条 `source=delivery` 的复验任务（main lane，无角色模板），有界复验次数后
   按未验证结果收口。判定写入 `summary["delivery"]`。`SECPT_ORCH_DELIVERY=0` 关闭。
5. **教练**：`coach.py` 在重试/RESET 的 objective 注入确定性纠偏（停止重复路线/缩任务/
   修前置条件/换路径）；Engine 内 StuckDetector + 可选 Mentor（`SECPT_MENTOR=1`）继续
   负责会话内卡壳介入。
6. **收尾复盘**：frontier 结束写 `var/jobs/<base>/retro.md`（战果/任务链/失败否定/
   交付判定），solve 的 learning 蒸馏继续把经验写入经验库并回写使用结果。
7. **入口**：solve 仍是唯一用户入口；入口输入是任务描述/题面 + 可选附件（`attachments/`
   或题面附件 URL），不再暴露多运行模式。

开关：`SECPT_ORCH_LOGISTICS=0`（关后勤）、`SECPT_ORCH_DELIVERY=0`（关交付门）、
`SECPT_ORCH_JEV=1`（外部 JEV 快判）、`SECPT_ROLE_TEMPLATES=1`（legacy 角色模板）。
benchmark profile 自动关闭后勤/交付门，保持跑分协议语义。

## 关键语义（Phase A 新增/变更）

### 1. bash 工具安全边界（A1.1）
- `shlex.split` + `asyncio.create_subprocess_exec` argv 数组执行，**禁 shell=True**
- 命令含 shell 元字符（`| ; & > < $ `` 等）默认拒绝；需要管道/循环时引导
  `write_file` 写脚本再执行
- 仅当 profile 显式把 `bash`/`sh` 加入白名单时才允许 shell 解释（`bash -c`）
- 输出读取有上限（BASH_READ_CAP），超时杀进程，不阻塞事件循环

### 1.1 上下文治理（实测调优）
真实靶场运行暴露并修复的连锁问题：
- **压缩/轮转阈值必须解耦**：compaction 阈值 0.72，但 rollover（重建链、丢 prefix
  cache）曾共用同一阈值——大输出场景压缩救场不及时，100 步触发 12 次轮转风暴。
  现 rollover 窗口阈值 0.95（最后手段），compaction 目标 0.5×window 批量删
- **尾部保护不能太大**：PROTECT_LATEST 12 → 6（12 条 8k 输出的保护尾本身
  就超阈值，压缩永远压不下去）
- **窗口按模型查表 + env 覆盖**：`MODEL_WINDOWS`（deepseek-flash=128k 等），
  `SECPT_CONTEXT_WINDOW=128000` 可显式覆盖（网关模型映射场景）
- 实测效果：压缩次数 68 步 21 次 → 全程 0 次（阈值 0.72 + 批量删）

### 2. 资源耗尽状态（A3）
`RunResult.status` 精确区分：

| status | 含义 |
|---|---|
| `success` | 拿到 ANSWER 正常终止 |
| `step_exceeded` | 步数用尽（≠超预算） |
| `wallclock_exceeded` | 墙钟到点 |
| `budget_exceeded` | 成本超预算 |
| `stalled` | 三档止损终态（wrapping 收尾 N 步仍无 ANSWER；编排层 RESET 重建或终态，见设计 §2/§3） |
| `failed` / `error` | 未拿到答案/引擎异常 |

`max_steps <= 0` 或 `max_wall_s <= 0` 表示**不限**（7×24 长任务）：
`secpt run --mode direct --objective-file t.md --wall 0`。
配合 compaction/rollover/watchdog 支撑长上下文长跑。

### 3. 协作式取消（A3）
SIGTERM → `WorkerCancelled` 在 on_step（步间）抛出 → round 快照已落盘，无损。
兜底强杀窗口 3s → 240s（覆盖最长 180s LLM 调用）；只有 engine 真正 hang 死才强杀。

### 4. 多模型路由（A4，`runtime/llm/client.py`）
OpenAI 兼容端点统一调用，`resolve_model()` 解析：

| 模型名 | 端点 | key 环境变量 |
|---|---|---|
| `deepseek-chat`（裸名默认） | api.deepseek.com | DEEPSEEK_API_KEY |
| `deepseek/<model>` | 同上 | 同上 |
| `openai/<model>` | OPENAI_BASE_URL（默认官方） | OPENAI_API_KEY |
| `<自定义>/<model>` | `SECPT_MODEL_BASE_<PREFIX>` | `SECPT_MODEL_KEY_<PREFIX>` 或 `_KEYENV_` |

重试：429/5xx/读超时/连接错误/连接超时/池超时，指数退避 4 次。
非 OpenAI 兼容协议需先接入其 OpenAI 兼容端点再用本客户端。

### 5. AI 评判层（A2，替代 flag 正则）
`secpt judge <job_id> [--ground-truth FILE] [--rubric FILE]`：

1. **anticheat**（确定性）：ANSWER 值是否在工具输出中（幻觉检测）；
   本地直读答案文件且命中 → 直接零分（远端 curl 读 flag 属合法利用，不误伤）
2. **Jev 门控**：TypeSafe System One typed decision（yes/no + 校准概率），
   高置信采信；`JEV_API_KEY` 未设置时自动降级
3. **LLM judge 终裁**：rubric（题面自动生成或 `--rubric` 显式提供）+ 证据 →
   结构化 verdict
4. **heuristic 兜底**：judge 不可用时有自报答案且无作弊信号 → 低置信通过

产出 `var/jobs/<id>/verdict.json` + events.jsonl `verdict` 事件。

## 插件工具与多阶段（需求3）

### 插件（tools/plugins/）
声明式 YAML：name/description/schema(OpenAI function)/run(命令模板)/timeout_s。
模板 `{参数}` 经 shlex.quote 替换、argv 数组执行（禁 shell=True）；schema 未声明的
参数拒绝；profile 的 `tools:` 或 stage 的 `tools:` 声明插件名即装配。
Python 插件（*.py 暴露 `register() -> {name: (schema, fn)}`）给需要编程能力的工具。
内置编程插件：
- `session`——pty 命名有状态会话（open/send/read/close/list；解决 su/ssh/mysql 等
  多步握手的一次一调用瓶颈；初始命令 argv 数组 + 白名单/scope 同口径治理，
  空闲 1800s 自动回收，最多 8 个）
- `http_request`——结构化 HTTP 原语 + raw 字节模式（走私/畸形请求研究；
  TLS 默认校验——红线不关；host 过 scope）
- `traffic`——录制流量武器化（list/replay/fuzz_param：确定性回放 + 单参数
  差分 + marker 命中检测；replay 库在 src/secpt/traffic/replay.py）

### 多阶段（profile.stages → 折叠意图链，S6）
`secpt solve -p multistage` 顺序执行 recon→getshell→privesc——S6 起由
`run_frontier(stages=...)` 承接（原 stages.py 执行器退役）：
- 每阶段 = 一条意图（role=阶段名，独立 job `<base>-i<id>`，可单独 resume/tail）
- 阶段串行：depends_on 前一阶段 intent_id；交接复用 M1 同资产 asset_state
  产物搬运（全链共用 asset_scope `stages:<profile>`）
- 中间阶段的 ANSWER 是阶段交付物（stop_on_first_flag=False 保证全链跑完）；
  阶段预算/工具/收尾条件映射意图 max_steps/max_wall_s/tools/done_criteria
- 阶段预算 0 值 → default_max_steps（solve --steps）/profile 预算

## 人在环路（ARTEX 模式②③，D1）

三种工作模式（同队列不同源，可运行时切换）：
- **自主探索**（默认）：solve/hunt，planner 产意图（source=planner）
- **人工直投**：`secpt intent add --job <base> "<要测什么>"`（source=direct，priority 9 插队；
  F1 后意图库按任务隔离，base 用 hunt/solve 启动时打印的 job 号）——
  planner 见 direct 未完成即暂停，执行完即停（人点单、AI 干活）
- **中途纠偏**：`secpt steer <job_id> "提示"`——SteerHook 每步从 var/steer.sqlite
  拉消息注入为 user 消息（不打断、不丢进度）；留痕可审计
- **关键节点把关**：拦截审批 `governance/intercept.py`——规则(SQLite 可管理，
  内置种子只拦毁灭性命令：rm -rf/dd/mkfs/shutdown→ask)；ask 阻塞等
  `secpt approve|deny <id>`（超时默认 deny）；拦截消息标注"平台管控·非目标防御"
  （防模型当 WAF 绕过）；SECPT_INTERCEPT=0 全局关，SECPT_INTERCEPT_DEFAULT=ask 收紧

### frontier v2（D2）
intents 支持 `depends_on`（intent_id 或 `fact:谓词`，intel 图存在即解锁——
攻击链按依赖推进）；`max_workers>1` 时并发 claim（SQLite 单写原子认领）；
settle 通过 wake_queue 事件唤醒 planner（D2.3 钩子，默认顺序轮询）；
`search_traces` 工具跨 job 检索执行过程（ARTEX 原则 5，worker 互查中间日志）。

**五角色闭环（orchestrator/roles.py，legacy）**：recon→exploit→lateral→verify→report。
v3 默认不使用；`SECPT_ROLE_TEMPLATES=1` 时才注入角色 planner/role_stage。lateral（横向移动）
由 `depends_on="fact:credential"` 事实门控——exploit/recon 的角色 prompt 硬约束拿到凭据必须
record_fact（credential:/access:/vuln: 前缀），intel 图出现凭据事实即确定性解锁横向意图
（role_plan 预置骨架含 1 条 lateral；同机制仍可供通用 planner 的显式依赖声明使用）。

**调度硬化（复评修复轮）**：
- 意图库按任务隔离：`var/jobs/<base>/frontier.sqlite`（此前全项目共享
  `var/frontier.sqlite`→并发任务互抢意图、`total()` 终身配额掐死 planner）
- 资产级在途互斥：带 `asset_scope` 的意图 claim 时原子抢占 `asset_leases`
  租约（settle/崩溃恢复释放）——同资产意图不并发；等待者见"已完成广播"直接
  跳过结算。run_frontier 另有任务级 flock 单编排锁（同 base 并发启动拒绝）
- 复核纪律运行时强制：首轮失败自动回队一次（重跑带最新事实上下文），
  硬止损类（意图级步数/引擎 error/预算超限）不复核
- recon→exploit 资产传递强保证：recon 的 `ws/assets.json` 由编排层确定性
  灌入 intel 资产图（不依赖模型自觉 observe_asset）
- 人机通道：`secpt intent add/set/rm`（直投/编辑/撤回，均需 `--job <base>`）
- JobManager（`secpt forever`）重启时从 jobs 表恢复排队任务，优先级取

## 长任务 / 多意图增强（2026-10-17，A/B/C 三阶段）

以 tsec1-run-1323 的真实跑分数据（63 题、4h39m、15,900/23,000）为输入，落地
"战役调度 + 多旗分解 + 验证闭环"三层能力（详见 `benchmark.py` / `frontier.py` /
`learning/playbook.py`）：

- **A1 多旗分段**：≥4 旗的题按 2 旗/段拆意图（`chunk_ranges`），同题 `asset_scope`
  串行、优先级保证段序；每段独立结算，拿一旗立即计分。平台通关时
  `finish_open_by_asset` 把剩余段直接落 done（不浪费步数）。≤3 旗保持单意图。
- **B1 verify 意图**：≥4 旗题在段后追加 `role=verify` 的独立复验意图（20 步），
  用新请求复验平台进度并扫剩余旗；benchmark 下只有 exploit/verify 角色广播
  scope_done（分段完成 ≠ 资产完成，防止误让出/跳过后续段）。
- **A2 campaign**：`run_benchmark_campaign` 自动多轮（`SECPT_CAMPAIGN_ROUNDS`，
  默认 3）；轮间用 `release_own_claims` 释放本进程租约，未完成题带 settle digest
  进入下一轮；`SECPT_CAMPAIGN_WALL_S` 控总墙钟。战役状态持久化到
  `var/campaigns/<task>.json`（C1）。
- **A3 期限与健康**：心跳线程每 60s 探平台，`BenchmarkEnded`（invalid_state /
  task_not_found）触发 `should_drain` → frontier 停止认领新意图、在途链自然收尾；
  轮末跳过容器清扫（平台已结束时逐个 close 只会空转）。`api.py health` 提供

- **B3 大输出**：bash 超长输出落盘后返回"头 6KB + 尾 2KB + 路径"（尾部命中不丢，
