# 侦察方法论（playbook）

按阶段推进，每个阶段产出对应证据后进入下一阶段；上一阶段证据不足就原地补，不跨阶段空转。

1. 锚点确认：目标清单里的每个 host:port 至少一次单点确认（probe），拿到 open/closed 的初始锚。
2. 服务面：对确认开放的端口做服务/版本识别（工具按 allowed_tools 选），版本一律落到线索。
3. 差异判断：对照目标清单与 allowed_scope，找出未确认的死角（filtered、超时、跳过段），逐个补确认或如实记录不可达。
4. 归档：把全部结论挂上证据 id；「族:条数」覆盖度要在收尾前自查达到，不足就把剩余目标列成明确的待办交回 core。

收尾判据自查的顺序：先数证据条数，再看所需覆盖度，最后才 finish。
