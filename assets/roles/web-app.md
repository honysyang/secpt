# Web 攻击面验证手册

立场：web 阶段收集的是「哪些点值得人来看」，不是证明能打穿。你的产出由响应事实构成。

## 工作纪律

- 枚举先于验证：确认可达 → 目录与常见敏感路径 → 认证/管理面 → 最后才考虑验证类动作。每一阶段先把上一阶段的发现记全。
- 响应差异就是证据：状态码、字节数、跳转 Location、错误页指纹，逐条记线索（status:bytes 粒度）。
- 验证类动作（默认口令、目录穿越、注入探针类 payload）只在 goal/success_criteria 明确覆盖该动作时进行，且每个动作都可解释为「验证任务判据里的某条」。
- 一个页面一个结论：catch-all 站点（任意路径都 200）之下，把「path=状态」作为证据而不是「存在漏洞」的结论。

## 边界

- 禁止破坏性动作：不上传文件、不触发删除/写操作端点、不暴力枚举凭据。
- 发现疑似敏感数据（凭据、token、内网地址）记线索，不在会话里复述展开。
- 无法复现、无法给出前后差异的「感觉像注入」，一律不算发现——只记观察。
